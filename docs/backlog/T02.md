## Context và mục tiêu

Các phiên agent không chia sẻ trí nhớ. Hợp đồng dữ liệu là nguồn chung để backend, UI và agent hiểu task, trạng thái và kết quả giống nhau.

## Đầu vào và điều kiện bắt đầu

- Đọc yêu cầu chung và đầu ra của các ticket phụ thuộc; xác minh code hiện có trước khi tạo module mới.
- Các tên module/đường dẫn đề xuất có thể điều chỉnh theo repo, nhưng phải giữ hợp đồng công khai và ghi lại quyết định.
- Nếu dependency chưa triển khai, có thể dùng adapter/fixture cho phần độc lập; không đánh dấu hoàn thành khi tích hợp bắt buộc còn thiếu.

## Phạm vi triển khai

1. Định nghĩa runtime schema và TypeScript types cho Project, Workflow, Task, AgentRun, Artifact, Approval, Finding và event.
2. Tách trạng thái task khỏi trạng thái run; có schemaVersion, ID, timestamp UTC, revision; task có dependencies và run có attempt/role/workspace.
3. Artifact gắn projectId, producerRunId, loại, version và đường dẫn; Approval tham chiếu chính xác document bundle/version hoặc hash.
4. Định nghĩa output envelope gồm outcome, summary, artifactRefs, findings, questions và metadata kiểm tra; chi tiết theo vai trò được mở rộng có version.
5. Thêm fixture hợp lệ/không hợp lệ; ghi quy tắc chuyển version và cách xử lý schema chưa hỗ trợ.

## Tiêu chí nghiệm thu và kiểm chứng

- [x] Schema từ chối enum sai, thiếu ID và kết quả không đúng vai trò; báo lỗi có đường dẫn field.
- [x] Có thể biểu diễn needs_input, failed, cancelled, interrupted và blocked mà không nhầm với completed.
- [x] Có fixture bao phủ một handoff docs, một code commit và một báo cáo test.

## Ngoài phạm vi

Không triển khai persistence hay suy luận workflow trong schema.

## Đầu ra và bàn giao

Package contracts, ví dụ JSON và tài liệu schema dùng cho T03/T06/T08.

Khi hoàn thành, cập nhật trạng thái ticket và ghi:

- File/module đã thay đổi và quyết định kỹ thuật đáng chú ý.
- Commands kiểm chứng đã chạy, kết quả thực tế và kiểm tra chưa chạy kèm lý do.
- Contract/artifact mà ticket tiếp theo phải sử dụng; giới hạn hoặc blocker còn lại.
