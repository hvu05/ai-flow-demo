## Context và mục tiêu

AI Flow không dùng database. File JSON theo project phải đủ an toàn khi FE/BE hoàn thành gần nhau hoặc backend bị dừng giữa lúc ghi.

## Đầu vào và điều kiện bắt đầu

- Đọc yêu cầu chung và đầu ra của các ticket phụ thuộc; xác minh code hiện có trước khi tạo module mới.
- Các tên module/đường dẫn đề xuất có thể điều chỉnh theo repo, nhưng phải giữ hợp đồng công khai và ghi lại quyết định.
- Nếu dependency chưa triển khai, có thể dùng adapter/fixture cho phần độc lập; không đánh dấu hoàn thành khi tích hợp bắt buộc còn thiếu.

## Phạm vi triển khai

1. Xây repository layer cho project/workflow/tasks/runs/approvals/artifacts; DATA_ROOT cấu hình qua env.
2. Dùng ghi file tạm cùng filesystem rồi rename và khóa cập nhật theo project; kiểm tra revision để phát hiện stale write.
3. Với thay đổi nhiều file, có journal hoặc cơ chế đối soát để phục hồi cập nhật dở; không coi nhiều rename là một transaction nguyên tử.
4. Validate dữ liệu lúc đọc/ghi; file hỏng phải được giữ để điều tra và trả lỗi, không tự thay bằng dữ liệu rỗng.
5. Chuẩn hóa đường dẫn, chặn traversal và truy cập chéo project; ghi rõ chỉ hỗ trợ một backend writer trong MVP.

## Tiêu chí nghiệm thu và kiểm chứng

- [x] Hai cập nhật đồng thời không làm mất task/run của nhau.
- [x] Mô phỏng dừng giữa cập nhật: restart phát hiện/khôi phục nhất quán hoặc báo blocked rõ ràng.
- [x] JSON hỏng, schema lạ và đường dẫn thoát DATA_ROOT được xử lý có lỗi kiểm soát.

## Ngoài phạm vi

Không thêm ORM, SQL, cloud storage hoặc nhiều replica backend.

## Đầu ra và bàn giao

Repository services, layout dữ liệu, kiểm thử concurrency/recovery và hướng dẫn backup.

Khi hoàn thành, cập nhật trạng thái ticket và ghi:

- File/module đã thay đổi và quyết định kỹ thuật đáng chú ý.
- Commands kiểm chứng đã chạy, kết quả thực tế và kiểm tra chưa chạy kèm lý do.
- Contract/artifact mà ticket tiếp theo phải sử dụng; giới hạn hoặc blocker còn lại.

## Ghi chú triển khai

Hoàn tất ngày 2026-09-16.

- apps/api/src/storage: repository interface + NestJS injection token/module; JSON implementation cho project/workflow/task/run/approval/artifact/finding/event.
- Khóa theo project trong cùng process, optimistic revision checking, atomic temp-write/rename/fsync, journal before/after và roll-forward idempotent trước đọc/ghi.
- Chặn ID traversal, symlink/hardlink file, ownership mismatch; JSON/schema hỏng được giữ nguyên và trả StorageError có code.
- Update/delete có revision guard. deleteProject logical-delete vào DATA_ROOT/.trash, giữ files để phục hồi; chưa có HTTP CRUD (T10).
- npm run check: typecheck/lint/build đạt, 46 tests đạt (24 contracts + 22 storage).
- Test storage có child process thật bị SIGKILL sau journal và sau entity đầu tiên; instance mới phục hồi đủ transaction. Có tests concurrent task/run, stale update, partial JSON prevention, corruption, schema lạ, paths, CRUD, journal divergence.
- npm run test:browser: 1 test Google Chrome thật đạt sau tích hợp StorageModule; UI kết nối API, hiển thị lỗi và retry.
- docs/storage.md ghi API, layout, recovery, backup/restore và giới hạn. Bàn giao PROJECT_REPOSITORY cho T07/T10; DATA_ROOT lấy từ root .env, mặc định ./data.
- Giới hạn theo scope T03: chỉ một backend process/writer, local Linux filesystem; không có distributed/process lock, không ghi JSON bằng công cụ khác trong khi API chạy. Artifact blobs/log writing thuộc các ticket sau, metadata artifact ở artifacts/*.json.
- Không còn blocker cho T01–T03. Docker, Codex runner và workflow nghiệp vụ chưa nằm trong ba ticket này.
