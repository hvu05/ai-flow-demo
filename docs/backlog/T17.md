## Context và mục tiêu

FE Agent nhận một nhiệm vụ hữu hạn và contract đã duyệt, làm trong worktree riêng. FE có thể phát triển khi BE chưa chạy bằng dữ liệu mô phỏng đúng contract.

## Đầu vào và điều kiện bắt đầu

- Đọc yêu cầu chung và đầu ra của các ticket phụ thuộc; xác minh code hiện có trước khi tạo module mới.
- Các tên module/đường dẫn đề xuất có thể điều chỉnh theo repo, nhưng phải giữ hợp đồng công khai và ghi lại quyết định.
- Nếu dependency chưa triển khai, có thể dùng adapter/fixture cho phần độc lập; không đánh dấu hoàn thành khi tích hợp bắt buộc còn thiếu.

## Phạm vi triển khai

1. Tạo prompt FE gồm task, criteria, design/contract version, baseline, allowed paths và scripts kiểm tra.
2. Triển khai màn hình/luồng cần thiết, loading/empty/error states; không tự đổi API contract.
3. Khi contract thiếu/sai, trả design-change finding thay vì sửa ngầm shared interface.
4. Chạy test/lint/build phù hợp, stage file có chủ đích và tạo commit; lưu command/result và known limitations.
5. Backend kiểm tra changed paths/commit; sửa shared file ngoài quyền chuyển integration task, không âm thầm nhận.

## Tiêu chí nghiệm thu và kiểm chứng

- [ ] Commit thuộc FE worktree và liên kết task/criteria/contract đúng version.
- [ ] UI dùng đúng request/response/error contract; có kiểm thử hành vi quan trọng.
- [ ] Thiếu BE runtime không bị báo hoàn thành integration test giả; mock được ghi rõ.

## Ngoài phạm vi

Không sửa code BE, merge delivery branch hoặc mở PR riêng.

## Đầu ra và bàn giao

FE role runner adapter, commit handoff, test report và fixtures workflow.

Khi hoàn thành, cập nhật trạng thái ticket và ghi:

- File/module đã thay đổi và quyết định kỹ thuật đáng chú ý.
- Commands kiểm chứng đã chạy, kết quả thực tế và kiểm tra chưa chạy kèm lý do.
- Contract/artifact mà ticket tiếp theo phải sử dụng; giới hạn hoặc blocker còn lại.

## Ghi chú triển khai

Chưa triển khai. Không có kết quả kiểm chứng ở thời điểm viết ticket.
