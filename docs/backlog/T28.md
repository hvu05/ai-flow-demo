## Context và mục tiêu

Một màn hình cho người dùng quan sát agent nhận việc, bàn giao tài liệu/contract/plan và cuối cùng tạo FE nhỏ.

## Phạm vi triển khai

1. Thay màn hình health-only bằng nhập ý tưởng, start/cancel, flow 5 node và gate Duyệt; hiển thị Codex preflight.
2. Polling snapshot/log khi phù hợp; cleanup request/timer, loading/disconnected/error states và mở lại lượt gần nhất.
3. Node có role, trạng thái, thời gian và run ID. Click xem task/prompt, input files, output files và log giới hạn.
4. Đường bàn giao cho thấy producer → consumer, tên file, version/hash; người xem mở đúng dữ liệu đã được agent sau nhận.
5. UI duyệt bundle sau Planner: requirements/review/OpenAPI/plan; nút bật theo allowed actions từ backend và chống double submit.
6. Kết quả FE có file browser đơn giản, tải source, README và build status; nhãn rõ mock data/chưa có BE. Render Markdown an toàn, code chỉ hiển thị text, không chạy code sinh ra trong origin của app.

## Tiêu chí nghiệm thu

- [x] Người dùng theo dõi đủ 5 node, duyệt trước FE và đọc được đầu ra trên một trang.
- [x] Input/output/version của từng handoff khớp backend; không chuyển xanh bằng timer giả.
- [x] Reload, lỗi Codex, review cần sửa và cancel có trạng thái đúng.
- [x] FE source tải được, có hướng dẫn chạy và thông tin build/mock rõ ràng.

## Ngoài phạm vi

Không editor kéo thả, IDE nhúng, preview code tùy ý, search/history nâng cao hoặc dashboard nhiều trang.

## Bàn giao và kiểm chứng

UI một trang đã triển khai trong apps/web. 3 Playwright tests: auth/connection, handoff/Markdown/gate/hash/reload/download link, review blocked và mobile. Snapshot của các case flow là fixture được ghi rõ trong tests; backend health/latest dùng API thật. Download bytes được kiểm tra ở service test. Screenshot test-results/demo-approval-fixture.png và demo-mobile-fixture.png là UI fixture, không phải live demo. Các hành vi UI đã kiểm tra; tích hợp model thật của T27/T29 còn chờ nên chưa DONE.
