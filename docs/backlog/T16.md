## Context và mục tiêu

Project sinh ra khác ứng dụng điều phối: nó có Next.js, NestJS và PostgreSQL. Một baseline chung giúp FE/BE không tự tạo hai khung lệch nhau.

## Đầu vào và điều kiện bắt đầu

- Đọc yêu cầu chung và đầu ra của các ticket phụ thuộc; xác minh code hiện có trước khi tạo module mới.
- Các tên module/đường dẫn đề xuất có thể điều chỉnh theo repo, nhưng phải giữ hợp đồng công khai và ghi lại quyết định.
- Nếu dependency chưa triển khai, có thể dùng adapter/fixture cho phần độc lập; không đánh dấu hoàn thành khi tích hợp bắt buộc còn thiếu.

## Phạm vi triển khai

1. Dựng template versioned, scripts lint/test/build, env mẫu, healthcheck, DB migration entry và Compose cho generated app.
2. Chỉ scaffold vào workspace sạch sau approval; ghi template version và file manifest, không ghi đè dữ liệu có sẵn.
3. Tạo Git baseline tối thiểu làm base của PR, sau đó scaffold/application changes thuộc delivery branch; lưu base SHA để T22 publish repo trống đúng diff.
4. Tạo FE/BE worktree/branch từ scaffold commit chung; tách ownership thư mục và shared files.
5. Chuẩn hóa Git identity và runtime env; kiểm tra port/compose project name riêng cho từng project.

## Tiêu chí nghiệm thu và kiểm chứng

- [ ] Template build và boot được, healthcheck đạt, DB dữ liệu persist qua restart.
- [ ] FE/BE cùng baseline nhưng thay đổi file độc lập.
- [ ] PR dự kiến bao gồm scaffold và tính năng, không bị mất toàn bộ diff do base đặt quá muộn.
- [ ] Thư mục không rỗng hoặc retry scaffold không gây mất file/commit.

## Ngoài phạm vi

Không triển khai tính năng người dùng hoặc publish remote ở bước này.

## Đầu ra và bàn giao

Template, scaffold service, workspace manifest và smoke test.

Khi hoàn thành, cập nhật trạng thái ticket và ghi:

- File/module đã thay đổi và quyết định kỹ thuật đáng chú ý.
- Commands kiểm chứng đã chạy, kết quả thực tế và kiểm tra chưa chạy kèm lý do.
- Contract/artifact mà ticket tiếp theo phải sử dụng; giới hạn hoặc blocker còn lại.

## Ghi chú triển khai

Chưa triển khai. Không có kết quả kiểm chứng ở thời điểm viết ticket.
