## Context và mục tiêu

Nối Requirements → Docs Reviewer → API Contract → Planner → người dùng duyệt → FE bằng artifact thật. Không cần generic workflow engine hoặc nhánh song song.

## Phạm vi triển khai

1. Tạo 5 role prompts; thêm role api_contract và loại artifact OpenAPI nếu shared schema hiện tại chưa đủ, giữ tương thích records v1 đã có.
2. Requirements tạo PRD nhỏ; Reviewer trả PASS/CHANGES_REQUESTED; API Contract tạo OpenAPI JSON hợp lệ với examples; Planner tạo task FE tham chiếu contract/criteria.
3. Định nghĩa context cho mỗi vai trò từ file của producer trước, không dùng transcript của một session dài. Validate OpenAPI cấu trúc trước khi giao Planner/FE.
4. Sau Planner, lưu bundle immutable/hash gồm requirements/review/contract/plan; chờ người dùng duyệt đúng version. FE tuyệt đối chưa chạy trước approval.
5. FE dùng Next.js scaffold tối thiểu, fixtures/mock theo API contract; scope một trang/luồng nhỏ. Bàn giao source, README và kết quả build thật; không chạy backend ứng dụng. Chỉ backend xác nhận build bằng command preset, không tin lời agent.
6. API nhỏ: start/latest/snapshot/approve/cancel và đọc artifacts/log/download FE theo ID. Chỉ một lượt active; chống start/approve trùng.
7. Dùng JSON repository T03. CLI lỗi/review fail/needs_input/invalid output dừng; startup nhận diện interrupted và giữ lịch sử, không tự resume. Không tạo retry loop.

## Tiêu chí nghiệm thu

- [ ] Một lượt có 5 run IDs/session độc lập và input refs truy về đúng producer artifact.
- [x] OpenAPI được validate; Planner/FE dùng đúng contract được duyệt; stale/duplicate approval không tạo run mới.
- [x] FE không chạy trước duyệt; build output gắn đúng run/source và mock được ghi rõ.
- [x] Lỗi ở một node chặn node sau; reload/restart giữ kết quả và thể hiện interrupted trung thực.
- [x] Các endpoint artifact/download chặn traversal/truy cập nhầm project.

## Ngoài phạm vi

Không BE/Tester agents, generic DAG, GitHub, worktree, database, auto-fix hay embedded FE preview server.

## Bàn giao và kiểm chứng

Pipeline, API và Next.js builder đã triển khai trong apps/api/src/demo; prompts trong runner, schemas trong packages/contracts. Tests fixture chứng minh 5 run IDs, refs đúng producer, gate/hash, duplicate dispatch, review fail, output/OpenAPI sai, cancel, recovery và ownership. Một test build Next.js thật từ code fixture. Tiêu chí 5 phiên Codex thật và tích hợp live T26 vẫn chờ người dùng, nên chưa DONE.
