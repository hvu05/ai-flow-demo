## Context và mục tiêu

Chứng minh luồng 5 agent thật trong Docker và FE đơn giản build được; demo phải cho thấy bàn giao thực tế, không chỉ các test mô phỏng.

## Phạm vi triển khai

1. Kịch bản: người dùng mô tả app ghi chú cá nhân nhỏ; agent tạo requirements, review, API contract, plan; người dùng duyệt; FE dùng mock tạo giao diện.
2. Tests deterministic cho happy path, invalid output/OpenAPI, review fail, stale/duplicate approval, CLI error, cancel và reload. Fixture luôn ghi rõ fake.
3. Khi được người dùng cho chạy và đã xác thực Codex, chạy kịch bản qua Compose/UI. Tại gate phải chờ người dùng duyệt, không tự approve thay để hoàn thành nghiệm thu.
4. Thu report với 5 run/session IDs, timestamps, producer-consumer refs/hash, artifact và screenshots. Xác minh FE build thực tế; không tuyên bố API thật hoạt động.
5. Recreate container rồi mở lại run/artifacts/source; README có setup Docker/auth, lệnh chạy, kịch bản và cách xử lý lỗi.
6. Nếu live run, user approval hoặc Docker kiểm chứng chưa thực hiện được thì giữ ticket chưa DONE và ghi rõ blocker/kiểm tra chưa chạy.

## Tiêu chí nghiệm thu

- [ ] Một lượt thật đi qua 5 phiên độc lập trong Docker, dừng đúng gate duyệt và bàn giao đủ files.
- [ ] Code FE dùng mock phù hợp contract, build được và người dùng lấy source/chạy theo README được.
- [ ] Compose recreate giữ dữ liệu; credential không lộ trong report/log.
- [x] Tests kiểm tra lỗi và duplicate dispatch đạt; report phân biệt fake tests với live demo.

## Ngoài phạm vi

Không nghiệm thu BE thật, tester agent, PR, production deploy hoặc đầy đủ T04–T24.

## Bàn giao và kiểm chứng

Đã viết docs/demo-guide.md và README; báo cáo tại docs/verification-demo.md. Tests deterministic và kiểm chứng Docker đã thực hiện, chưa gọi model, chưa duyệt thay người dùng. Live run, FE sinh bởi agent thật và giữ source của lượt thật qua recreate còn chờ người dùng thực hiện. Giữ IN_PROGRESS.
